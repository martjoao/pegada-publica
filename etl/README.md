# ETL — Stage 1 (data collection)

Python scripts that collect data from official government APIs/dumps and save it
to disk. This is the **Extract** stage: scripts fetch from source APIs and write
**raw landing files** under `data/raw/`. Parsing and loading into the local DB is
a separate later stage.

Fetched data in `data/` is **not** committed — it is regenerated by re-running
the scripts.

## Setup

Requires Python 3.8+. Dependencies are managed with `pip` + `requirements.txt`.

```bash
cd etl
python3 -m venv .venv            # or: python3 -m virtualenv .venv
source .venv/bin/activate
pip install -r requirements.txt          # runtime deps
pip install -r requirements-dev.txt      # + test deps (pytest, responses)
```

> If `python3 -m venv` reports `ensurepip is not available`, either install your
> distro's `python3-venv` package, or use `virtualenv` instead:
> `pip install --user virtualenv && python3 -m virtualenv .venv`.

## Available scripts

### Câmara — deputy roster

Fetches the full list of deputies for the in-scope legislaturas (56ª and 57ª)
from the Câmara dos Deputados open-data API.

```bash
python -m pegada_etl.sources.camara.deputados
```

Writes one file per legislatura:

```
data/raw/camara/deputados/legislatura-56.json
data/raw/camara/deputados/legislatura-57.json
```

Each file is provenance-wrapped:

```json
{
  "_meta": {
    "source": "camara-dados-abertos",
    "endpoint": "/deputados",
    "legislatura": 57,
    "fetched_at": "2026-05-31T15:08:07Z",
    "record_count": 870
  },
  "dados": [ /* deputy records, exactly as returned by the API */ ]
}
```

The record count exceeds the 513 seats because a legislatura's roster includes
everyone who held the seat during the term (e.g. substitutes/suplentes).

## Layout

```
pegada_etl/
├── paths.py              # where raw landing files go (data/raw/...)
├── http_client.py        # CamaraClient: retry/backoff + auto-pagination
└── sources/camara/
    └── deputados.py       # the deputy-roster extract
tests/                    # pytest, mocks HTTP via `responses` (no live calls)
```

## Tests

```bash
pytest
```

Tests mock the HTTP layer with `responses`, so they make no live network calls.
